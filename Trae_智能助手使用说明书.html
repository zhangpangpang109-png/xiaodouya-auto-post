Trae 智能助手使用说明书

这份说明书帮你快速上手：我是谁、和 Trae / Claude Code 是什么关系、各自区别是什么，以及你在日常开发中怎样更高效地使用我。

定位 对比 最佳实践

适合：自动化脚本开发、故障排查、项目重构、命令行执行、代码解释与文档沉淀。

1. 我、Trae、Claude Code 的关系

Trae（你的 IDE/工作台）

Trae 是你操作项目的编辑器和执行环境：打开文件、运行命令、查看输出、管理工程。

我（当前智能助手）

我是运行在 Trae 里的 AI 工程助手，能读写文件、执行命令、分析项目结构，并按你的目标推进任务。

Claude Code（另一类代码助手）

Claude Code 通常指 Anthropic 生态下的代码代理/工具形态。它和我属于不同产品路线，但目标类似：提高开发效率。

2. 关键区别（你最关心的）

  • 载体不同：Trae 是 IDE；我是 Trae 内的助手；Claude Code 是另一套助手体验/工具链。
  • 交互方式不同：我可直接结合当前工作区文件与命令执行结果持续迭代。
  • 模型来源可配置：你可以通过网关或配置切换底层模型，但使用方式（提需求→执行→验收）可以保持一致。

注意：助手名称与底层模型名称不是一回事。你看到的是“助手体验”，底层可能随网关策略动态映射。

3. 日常怎么更好地用我（高效模板）

3.1 给任务时，尽量包含 4 要素

  • 目标：你最终要什么结果（例如：生成可运行脚本）。
  • 范围：修改哪些文件/目录，哪些不能动。
  • 标准：成功判定（比如“能跑通、日志清晰、失败可重试”）。
  • 约束：语言、风格、依赖、系统环境。
示例：
请在 xiaodouya_poster.py 上加“发布失败重试3次”，
不要改配置文件结构，给我最小改动补丁并说明回滚方法。

3.2 让助手更稳的 5 个习惯

  • 先让我“读文件+总结现状”，再让我改代码。
  • 复杂需求拆步骤：先设计，再实现，再测试。
  • 明确“是否可执行命令、是否可联网”。
  • 要求“变更说明 + 风险点 + 验证命令”。
  • 每次改完让助手给你“下一步建议”。

4. 推荐工作流（可直接照抄）

  1. 你：先说目标与限制。
  2. 我：先读相关文件并总结。
  3. 你：确认方案后让我实施。
  4. 我：改代码、跑命令、回传结果。
  5. 你：基于结果继续迭代或收尾。

一句话：把我当“会动手的结对工程师”，而不只是聊天机器人。

5. 安全与密钥建议

  • 不要在长期聊天记录中暴露真实 API Key。
  • 如果已泄露，立即撤销并重建密钥。
  • 将密钥放到环境变量或受控配置，不要硬编码进仓库。
